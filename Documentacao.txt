📘 Documentação Técnica: Projeto Prombox (Frontend)

Cliente: TKS Vantagens

Projeto: Plataforma de Sorteios e Premiações (Prombox)

Versão: 2.2 (Estável - Com Carrossel 3D CSS-Only)

Responsável Frontend: Igor Soares

1. Visão Geral e Objetivos

O projeto Prombox é uma Landing Page de alta conversão focada na venda de cotas para sorteios online (rifas). A arquitetura foi desenhada priorizando:

Performance: Uso de CSS puro para animações complexas (como o ticker e o carrossel 3D), evitando JavaScript pesado que trava em dispositivos móveis.

Identidade Visual: Rigorosa aplicação da paleta de cores da marca (Rosa Vinho, Amarelo Ouro e Azul Noite).

Conversão: Fluxo de compra simplificado com seleção de pacotes e feedback visual imediato.

2. Arquitetura de Pastas e Arquivos

A estrutura do projeto segue o padrão clássico de desenvolvimento web, facilitando a integração futura com frameworks PHP (Laravel/CodeIgniter) ou WordPress.

prombox-web/
├── assets/              <-- Recursos estáticos
│   └── images/          <-- (Logos, banners, ícones)
├── css/                 <-- Estilos
│   └── styles.css       <-- Cérebro visual (Variáveis, Animações, Overrides)
├── js/                  <-- Lógica
│   └── main.js          <-- Interatividade (Menu, Modal, Cálculos)
└── index.php            <-- Estrutura (HTML Semântico + PHP Básico)


3. Detalhamento dos Componentes (Frontend)

A. Cabeçalho (Header)

Arquivo: index.php (Linhas 25-80)

Comportamento: Fixo no topo (sticky), com fundo Azul Noite (.bg-prombox-dark).

Navegação: Links brancos que ficam amarelos ao passar o mouse (.nav-link:hover). O link ativo fica rosa.

Responsividade: No mobile, os itens são ocultos e substituídos por um botão "Hambúrguer".

B. Faixa de Notícias (News Ticker)

Arquivo: index.php (Linhas 82-105)

Visual: Faixa contínua rosa (.bg-prombox-pink) com texto branco.

Técnica: Animação CSS pura (@keyframes marquee-scroll) que move o conteúdo da direita para a esquerda. O conteúdo é duplicado no HTML para criar um loop infinito perfeito sem "buracos".

C. Seção Hero (Banner e Compra)

Arquivo: index.php (Linhas 108-180)

Banner Central: Imagem responsiva (max-w-4xl) centralizada, com efeito de hover sutil.

Seletor de Cotas:

Pacotes Rápidos: Botões (5, 10, 50, 100) que atualizam o input manual e o preço total instantaneamente.

Input Manual: Permite ajuste fino (+/-).

Cálculo: Realizado em tempo real no js/main.js (Função updateTotal), multiplicando a quantidade por R$ 0,99.

D. Carrossel de Depoimentos (Efeito 3D / Funil)

Arquivo: index.php (Linhas 183-220) e css/styles.css (Seção 8)

Conceito: Lista horizontal de vídeos estilo "Stories".

Efeito Visual:

Máscaras: Uso de elementos pseudo-3D (.mask-top, .mask-bottom) com bordas arredondadas e sombras para criar a ilusão de um cilindro ou funil.

Scroll: Rolagem horizontal nativa (overflow-x: scroll) com scroll-snap para que os vídeos parem sempre centralizados.

Performance: Zero dependência de bibliotecas JS externas (Swiper/Slick), garantindo fluidez total no mobile.

5. Instruções de Integração (Para equipe Backend)

Pontos de Injeção de Dados (PHP)

A equipe de backend deve substituir o conteúdo estático pelos dados vindos do banco de dados (MySQL/PostgreSQL).

Banner Principal:

Substituir src="./assets/images/banner_central.jpeg" pela URL da imagem do sorteio ativo.

Ticker de Notícias:

Gerar o loop dos <span> dentro de .prombox-ticker-wrapper com os últimos ganhadores. Atenção: É necessário duplicar o loop (imprimir 2x a lista) para que a animação infinita funcione corretamente.

Depoimentos (Carrossel):

Substituir o loop for ($i = 1; $i <= 15; $i++) por um foreach real.

O ID do vídeo do YouTube deve ser inserido dinamicamente no onclick="openVideoModal('ID_DO_VIDEO')" e na URL da thumbnail (img.youtube.com/...).

Checkout:

O botão "PARTICIPAR" chama a função JS checkout(). Esta função deve ser atualizada para:

Submeter um formulário POST oculto;

Ou redirecionar para o gateway de pagamento (Mercado Pago/Pagar.me) passando a quantidade (manualQty) e o valor total via GET/POST.

Scripts e Dependências

Certifique-se de manter o main.js no final do <body> para garantir que o DOM esteja carregado antes da execução dos scripts.

O Cache Buster (?v=<?php echo time(); ?>) no link do CSS deve ser mantido em desenvolvimento, mas alterado para uma versão fixa em produção para otimizar o carregamento.
